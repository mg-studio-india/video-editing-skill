# Program context

Program type helps decide delivery and pacing. It does not supply a story template. Story beats, claims, and visuals must come from the source footage, verified speech, brand materials, or explicit user direction.

## Contexts

- **Short social edit:** choose the platform's canvas and safe zones. Keep context necessary to understand the actual moment. A hook, payoff, or loop is useful only when the footage already supports it or the user asks for one.
- **Long-form talk:** preserve the speaker's reasoning and meaningful pauses. Use chapters or visual aids only where the source changes topic or needs explanation.
- **Vlog / documentary:** let places, actions, natural sound, and the real sequence of events lead. Do not invent a cold open, journey, or conclusion.
- **Product or process video:** use observed product shots and verified narration. No-dialogue shots remain story material; do not invent feature names, benefits, or equal-length sections.
- **Reference recreation:** study the supplied reference for visual grammar, pacing and framing. Rebuild those choices only where the user's footage can support them and the brand permits them.

## Planning checks

- What event, spoken line, or visual change makes each beat necessary?
- Does the sequence preserve the source's meaning and timing?
- Does the chosen format suit the actual source framing and intended platform?
- Are generated or sourced assets clearly identified and user-approved?

If there is no strong reason for an added treatment, keep the source picture clean and use the current simple captions.
